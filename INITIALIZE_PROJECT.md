# Prompt d'initialisation Escalia V7
Tu es Lead Frontend Engineer. Initialise un socle navigable, pas le produit métier complet. Lis AGENTS.md, les trois skills et tous les documents de référence. Le présent prompt fixe le périmètre autorisé ; si conflit, signale-le. Ne déploie rien.

## 0 — Audit
Inspecte dépôt, package manager, versions, licence et révision du template gratuit Studio Admin. Si dépôt vide, initialise depuis https://github.com/arhamkhnz/next-shadcn-admin-dashboard après vérification ; sinon adapte sans écraser. Vérifie MCP et dépendances compatibles. Préserve les 23 assets et manifeste. Planifie par étapes ; demande seulement les décisions bloquantes. Pas de dépendance premium.
## 1 — Foundation
Next.js App Router feature-first, TypeScript, Tailwind/shadcn, Barlow, tokens V7 light/dark/system, next-intl fr-CA/en-CA, next-themes si compatible. Installe seulement dépendances utiles (TanStack Query/Table, Zod, RHF, Sonner, Lucide, Recharts selon template). Lockfile, .env.example sans secrets, config validée. Logger serveur/client, redaction, correlation, instrumentation compatible, export distant off. Tests unitaires du logger.
## 2 — Shell
Header global 64px logo officiel, sidebar seamless pastel 232/56px, Medium+, breadcrumbs, recherche et notifications sur fixtures disponibles, aide et compte, FR/EN, thème. Pas de sélecteur rôle/organisation actif. Routes dashboard, properties, units, tenants, leases, payments, maintenance, documents, reports, settings ; futures pages traduites avec statut explicite, sans actions factices. Navigation réelle et responsive. Configuration profil/préférences/sécurité/confidentialité/notifications selon données disponibles ; préférences session vs permanentes selon architecture.
## 3 — Auth publique
Split screen 55/45, logo officiel, illustration architecturale, mobile formulaire seul. Login, register (prénom, nom, courriel, téléphone facultatif international, mot de passe selon IdP), forgot/reset/verify, session expirée, 403/404/500/maintenance. Liens privacy/terms sur tous écrans publics, pages bilingues provisoires clairement identifiées, conservation formulaire sans stockage du mot de passe. Sans IdP : écrans démonstratifs sans collecte de vrais credentials, entrée démo séparée explicite ; pas de faux succès inscription ni OAuth. Production fail closed. Si IdP réel fourni, intégrer uniquement contrats confirmés, session opaque, CSRF, cookies et protections selon architecture.
## 4 — Référence métier et BFF
Dashboard et liste/détail immeubles avec fixtures fictives étiquetées, recherche, filtres, pagination, retour contexte, graphiques et tooltip pastel. Exemple formulaire démonstratif sans mutation réelle. BFF liste/détail local explicitement documenté, DTO/Zod, service server-only, adapter fixtures, timeout, mapping erreurs et corrélation. Aucun endpoint upstream inventé. RSC appelle service directement, client interactif via BFF. Démo uniquement dev/test avec flag explicite, production refuse même si flag activé. Pas de RBAC, SaaS, abonnement, onboarding, rôle, audit ou workflow métier inventé.
## 5 — Composants et feedback
Inventorie template ; galerie dev des composants réellement utilisés, états loading/empty/error/success, validation, tooltip clavier/tactile, graphiques accessibles. Prépare contrats de compositions réutilisables sans implémenter tout catalogue. Respecte WebView First, pas de conteneur natif à créer. Cookies inventoriés, aucun tracking par défaut.
## 6 — Validation
Exécute installation, lint, typecheck, tests unitaires/intégration/e2e, build. Démarre localement ; Playwright MCP si disponible pour explorer et capturer dashboard, liste/détail, auth, configuration et galerie, light/dark, FR/EN, desktop/mobile. Playwright Test reproductible, axe-core et contrôle manuel clavier/contrastes ; matrice 1440/1280/768/390/320. Vérifie navigation, préférences, i18n, états BFF, redaction, corrélation concurrente, absence de secrets bundle, démo interdite prod. Ne prétends pas tester IdP/RBAC/WebView natif absents. Présente captures et écarts avant généralisation du style.
## 7 — Livraison
README applicatif avec commandes réelles, variables, architecture, démo et limites ; conserver README package ou intégrer son contenu. Documenter cookies, décisions, contrats et rapport de tests. Fournir fichiers modifiés, résultats exacts, blocages, hypothèses et prochaines étapes. Aucun déploiement.
## Definition of Done
Socle démarrable localement, navigation et thèmes/langues fonctionnels, référence dashboard/immeubles, assets intacts, sécurité fail closed, logs intelligents sans PII, tests et documentation. Si une vérification échoue, corriger ou déclarer le blocage ; aucune réussite fictive. Les fonctionnalités futures restent non implémentées.
