# Observabilité V7
## Objectif
Logs structurés utiles, corrélation navigateur/WebView → Next serveur → BFF → backend si supporté. Pino côté Node, abstraction client légère séparée, OpenTelemetry et instrumentation Next selon compatibilité, Web Vitals et Error Boundaries. Aucun fournisseur de centralisation imposé.
## Contrat
JSON UTC : timestamp, level, service, environment, layer, module, event, message anglais stable, correlationId, traceId/spanId si disponibles, durationMs, statusCode, errorCode et metadata allowlistée. Nommage domain.operation.outcome (buildings.list.completed, bff.upstream.timeout, ui.render.failed). Exemple : logger.info("buildings.list.completed", {durationMs:142,resultCount:24}). Contexte injecté par logger, pas de payload brut. TRACE diagnostic exceptionnel, DEBUG dev, INFO résultat significatif, WARN dégradation, ERROR échec inattendu, FATAL processus inutilisable. Pas de log par rendu/clic/frappe.
## Frontières
src/lib/observability/logger/{logger.server.ts,logger.client.ts,logger.types.ts,logger.config.ts,redaction.ts}, tracing/{correlation.ts,telemetry.ts}, errors/{application-error.ts,error-reporter.ts}, metrics/web-vitals.ts. instrumentation.ts et instrumentation-client.ts selon version. server-only pour Pino et secrets ; vérifier bundle. Générer ID serveur, valider longueur/format des IDs entrants, propager traceparent selon standard et contrat upstream ; ne jamais utiliser un ID comme autorisation. Contexte par requête, pas de global mutable. Mesurer durée monotone. Une erreur journalisée à la frontière responsable, éviter doublons ; erreurs attendues 4xx non systématiquement ERROR. Retry uniquement sûr/idempotent.
## Confidentialité
Allowlist stricte des champs, redaction récursive avant émission, y compris erreurs, stacks, URLs, headers et objets imbriqués. Interdire tokens, cookies, mots de passe, OTP, courriels, téléphones, noms, adresses, données bancaires, contrats et corps de requêtes/réponses. Ne pas journaliser identifiants personnels bruts. Aucun secret dans NEXT_PUBLIC. Logs navigateur non fiables : collecte distante désactivée par défaut ; si activée ultérieurement, schéma strict, taille/rate limit, auth appropriée, redaction serveur, anti-injection, échantillonnage et politique de confidentialité. Ne pas inventer endpoint de collecte. Échec du logger ne bloque pas l'opération métier. Pas de session replay ni analytics tiers par défaut.
## Environnements
Local DEBUG/pretty ; dev INFO JSON configurable ; test WARN/ERROR ou capture contrôlée ; prod INFO JSON, DEBUG désactivé par défaut, échantillonnage des succès selon politique, erreurs significatives conservées sous limites anti-abus. TRACE opt-in temporaire. Variables LOG_LEVEL, LOG_FORMAT, CLIENT_LOG_LEVEL, OTEL_ENABLED=false, OTEL_SERVICE_NAME=escalia-webapp, NEXT_PUBLIC_CLIENT_LOGGING_ENABLED=false ; valider config, ne pas exposer secrets. Export OTEL désactivé sans destination approuvée. Rétention, seuils, accès, destination et sampling à arbitrer avant production.
## Événements et tests
Démarrage, fin requête BFF, timeout, erreurs upstream, auth échouée/session expirée sans identifiant, erreur React, réseau dégradé, upload échoué, latence anormale selon seuil. Tests : redaction imbriquée et erreurs, corrélation concurrente, niveaux, absence de secrets, failure logger, séparation client/serveur. Aucun succès financier avant confirmation serveur. Logs techniques distincts de l'audit métier autoritatif backend.
